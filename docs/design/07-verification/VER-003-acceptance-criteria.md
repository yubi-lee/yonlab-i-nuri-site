# VER-003 Acceptance Criteria

## Design Acceptance

The design package is acceptable when:

- requirements cover public, member, administrator, security, operations, and verification concerns
- traceability connects requirements to design and verification
- CDD documents define component responsibilities and boundaries
- ICD documents define implementable contracts
- data model covers entities, relationships, constraints, indexes, lifecycle, UTC policy, privacy, audit, and transactions
- security controls address the threat model
- operations design covers deployment, rollback, observability, backup, and recovery
- verification design covers functional and non-functional requirements
- open decisions are identified with decision criteria

## Product Acceptance

Product acceptance requires successful verification of:

- public portal workflows
- member workflows
- authentication and session security
- administrator CMS workflows
- file storage workflows
- email delivery workflows
- search workflows
- audit and observability
- diagnosis scoring API validation, deterministic output, correlation, safe errors, and no raw evidence persistence
- security controls
- backup, restore, deployment, and rollback

## Clean-Room Acceptance

Product artifacts must be independently authored or properly licensed. Reference analysis must not be copied into product copy, layout, icons, images, source, or documentation.
